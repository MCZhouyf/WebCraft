# Review v12 W3: corpus and statistical reanalysis

Date registered: 2026-10-15 UTC. The author instruction is dated 2026-10-14.
This registration precedes every W3 result computation. The work is a
deterministic reanalysis of existing exports and corpus snapshots: it makes no
LLM call, runs no agent episode, and does not modify a frozen input, corpus
index, or ARBITER artifact. ARBITER inputs, when needed, are copied byte for
byte into `reports/paperA/inputs/` with source path and SHA-256 provenance.

## Common units and source precedence

- An instance key is `(task_id, condition, world)` after retaining seed
  `20261006`. The second deterministic seed is used only to assert bitwise
  identity. The 34-task evaluation matrix and feasibility labels come from the
  frozen main-experiment exports.
- A mechanism key is the frozen conflict/mechanism identifier after applying
  the existing normalizer. Families are fixed as `drop`, `recipe`, `smelting`,
  and `name`; an unrecognized identifier is retained as `other` and reported.
- Existing corrected, gold-path-reading, main-experiment, version-scoped, IAA,
  cost, and sensitivity exports are read as evidence. Existing reported values
  are not overwritten. Newly derived values are emitted as new files.
- All generated CSV files include source identifiers sufficient to trace a row
  back to its input. A source-hash manifest covers every input actually read.

## 1. Gold inventory and path coverage

The documentation will be derived from the exact symbols used by
`corpus/build_resolved_gold.py`, `corpus/gold_claims.py`, and
`corpus/block_templates.py`, not from remembered Wiki behavior. For each
condition, the available gold inventory is the union of gold claims attached
to chunks present in that condition's frozen index. A path mechanism is
covered when at least one inventory claim has the same normalized mechanism
family and subject, and its payload expresses the path assertion. Coverage is
the number of distinct covered oracle-path mechanisms divided by the number of
distinct oracle-path mechanisms across the 34 evaluation tasks, reported by
condition and family. A zero-denominator cell is `NA`, never zero.

The audit separately records whether the inventory contains claims for
`coal_ore -> coal`, `stone -> cobblestone`, and each observed cobblestone drop
variant, with claim ID, page, revision, timestamp, parser route, and payload.

## 2. Removed-claim hallucination audit

The census is the union of unique claim IDs actually depended upon by (a) the
54 originally successful Naive instances that degrade under corrected reading
and (b) the 59 Naive execution-failure instances that change under corrected
reading. Dependency is established only by an existing episode/evidence record
linking the claim or its compiled mechanism to the executed plan; mere
retrieval does not qualify. The cache-level sample is 100 unique removed claim
IDs drawn without replacement from the sorted full removed-claim population by
`random.Random(20261014).sample`.

For each claim, a deterministic candidate pass normalizes display names and
identifiers and locates the shortest span containing the subject plus a
family-specific cue: `drop/drops/dropped/obtain/mine` for drops,
`craft/recipe/ingredient` for recipes, `smelt/furnace` for smelting, and
`called/renamed/known as/name` for names. The table records match span and
character offsets. The first-pass label then uses this fixed priority:

1. `D`: the source supports the payload but explicitly scopes it as historical
   or to a particular version, whether in the same chunk or elsewhere on the
   page;
2. `A`: absent D, the same source chunk directly states the subject,
   relation, and payload;
3. `B`: absent D/A, another chunk or structured field on the same page directly
   states the same subject, relation, and payload;
4. `C`: neither the source chunk nor any available chunk/structured field on
   the same page states that payload.

Identifier/display-name normalization alone cannot upgrade a claim to A or B.
Every row includes source excerpt, supporting-page excerpt if any, deterministic
candidate label, first-pass label, reason, and a blank `author_review` column.
Instance summaries are mutually exclusive: `C_only` if all depended-upon
removed claims are C, `AB_only` if all are A/B, `mixed` otherwise (including D
or combinations with C). Instances with no traceable removed dependency are
reported separately and never forced into a category.

## 3. Corrected/gold inventory overlap

The universe is the frozen 286 feasible instance keys. For each key:

- `A_corr` is the set of normalized oracle-path mechanisms for which at least
  one retained or payload-corrected claim occurs in a retrieved corrected
  result before the terminal decision;
- `A_gold` is the set of normalized oracle-path mechanisms supplied by the
  gold-path-reading intervention for that key;
- `G` is the set of oracle-path mechanisms covered by the condition-specific
  gold inventory defined above.

Set equality and subset checks are exact on normalized IDs. The 58-success
test compares the corrected and gold success-key sets against keys satisfying
`path_mechanisms <= A_corr` and `path_mechanisms <= A_gold`; it reports both
directions of mismatch rather than redefining the criterion. The A/B gap is
the number of distinct oracle-path mechanisms supported by an A/B census claim
but absent from `G`.

## 4. Mechanism sensitivity event counts

Rows and prior judgments in `mechanism_sensitivity.csv` are retained. For each
row's listed task subset, new counts are derived from the same exports used by
the original analysis: unique instance count, Naive HTR-commit event count,
Verify-All probe-event count, pairable conflict-instance count in the mismatch
contrast, and feasible external-instance count. A conclusion with zero events
for the event type that identifies it is relabeled `不可估计（无事件）`; a
nonzero event that loses an effect retains the prior `消失` label.

## 5. Paper table generator

`reports/paperA/build_paper_tables_v13.py` reads CSV/JSON inputs only and emits
Markdown and HTML under `reports/paperA/paper_tables_v13/`. It generates Table
4, Table 6, G5, IAA, Version-Scoped, F1, F3, and the cost table. Every table has
explicit expected column names, row/cardinality assertions, uniqueness checks,
and registered anchor-value assertions drawn from its source export. Markdown
and HTML are rendered from the same in-memory rows. The generator records
input hashes and the RNG-correction note for shared-resampling intervals.

Table 5 and Appendix E are conditional: they are generated only when an A3
input manifest identifies committed `unified_110.csv` and `confusion_v3.csv`
and both files pass schema/hash checks. Their absence is reported as pending,
not synthesized from an older metric version.

## Failure and reporting rules

Missing provenance, non-identical deterministic seeds, duplicate instance
keys, an untraceable required dependency, or failed table assertions stop the
affected analysis and are reported. No rule, sample, label priority, or
denominator is changed after seeing outputs. Results are reported even when
they contradict the anticipated counts or manuscript interpretation.
