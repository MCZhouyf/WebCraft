# W16 zero-call reanalysis package II (post-review V)

Registered before computation on 2026-10-20 UTC. This analysis uses only frozen
exports and logs. It makes no network or LLM calls, launches no episodes, changes
no frozen task, truth, corpus, or method asset, and writes only W16-derived files.
`webcraft/` is a read-only input.

## Registration checks

The analysis is deliberately performed in two checks before interpreting results:

1. Validate source identity, denominators, condition names, and pair keys before
   computing any estimate. A source that does not cover its requested population is
   reported with its actual coverage and is not extrapolated.
2. Validate that resampling respects the registered independent unit: CDS family for
   CDS estimates and the five held-out task connectivity components for main-matrix
   estimates. No episode-level resampling is substituted for these units.

All point estimates are empirical means over the registered eligible rows. Bootstrap
intervals are percentile 95% intervals from 10,000 resamples generated by NumPy
PCG64 with seed `20261019`. A paired contrast uses the intersection of its two
conditions by `instance_id`; a missing pair is excluded and counted in the output.

## 1. ReAct GLM-5.2 CDS S-condition and factorial analysis

Input is the frozen A8 ReAct GLM-5.2 CDS episode export. The registered scope is
the five conditions `K+S`, `K`, `S`, `empty`, and `K+N`, each expected to contain
52 episodes. Direct, Qwen, and the pipeline/chain suite did not run condition `S`
and are outside this analysis.

The reported S metrics are: SR (`success`); feasible SR (`feasible_success` among
`true_feasible=1`); OC (`overconservative` among `true_feasible=1`); stale-specific
contact (`discriminative_stale_contact`); and propagation (`v3d_lower`). Results are
episode means with CDS-family-cluster bootstrap intervals. S contrasts are `S-empty`,
`S-K`, and `K+S-S`, separately for SR and stale-specific contact.

For the 2x2 analysis, correct knowledge is present in `K+S` and `K`; stale knowledge
is present in `K+S` and `S`. For each of SR and contact, the registered estimands are:

* correct-knowledge main effect: mean(`K+S`,`K`) - mean(`S`,`empty`);
* stale-knowledge main effect: mean(`K+S`,`S`) - mean(`K`,`empty`);
* interaction: (`K+S` - `K`) - (`S` - `empty`).

Cluster bootstrap samples whole `family_id` groups with replacement and retains all
their rows. If a resample has no eligible denominator for feasible-only metrics it is
dropped for that metric and the usable draw count is reported.

## 2. Human-audit sensitivity

The requested target is the held-out 110-instance comparison of each audited agent
against Naive. Before calculation, the final human audit export is joined by
`(method, condition, world, task_id)`. If it does not supply complete labels for the
110-instance population and paired Naive rows, no full-110 estimate is reported.
Instead, the output is explicitly limited to the exact audit-covered paired subset;
no imputation, weighting, or extrapolation is allowed.

`Spec` is the human stale-specific-contact indicator. `查询` and `执行` are confirmed
positive contact; `无` is confirmed negative; `无法确定` is undetermined. Two registered
schemes are computed once:

* **exclude-undetermined:** remove any paired comparison with an undetermined human
  label in either member, then compute agent-minus-Naive mean contact;
* **confirmed-positive-only:** retain all paired audit rows and count only `查询` or
  `执行` as positive; `无` and `无法确定` contribute zero.

The frozen comparator is the scorer's `scorer_contact` on the same paired rows. The
reported sensitivity is human delta minus frozen scorer delta. The pre-existing CDS
`K+S-K+N` audit-corrected value (+17.3 pp) is quoted as existing evidence only and
is not recomputed here.

## 3. Main-matrix connectivity-component sensitivity

For the two RQ2 upper-table Naive SR contrasts, use one deterministic representative
per held-out task after checking duplicate seed records are identical. The contrasts
are `matched_1.21.11 - mismatched_old2new` at world 1.21.11 and
`matched_1.16.5 - mismatched_new2old` at world 1.16.5. The point estimate pools the
34 task differences. Bootstrap resampling treats the registered five connected
components (MC1=19 tasks, MC2=12 tasks, and three singleton components) as the only
independent units. Every sampled component retains all of its task differences; the
resampled estimate is task-weighted. The output reports the frozen comparison when
available but does not overwrite it.

## 4. Existing-record cost summary

One row is emitted for every method family that has an existing frozen source. Fields
are LLM calls, CNY cost, mean semantic actions per episode, mean retrieval calls per
episode, and recorded replay duration. A field absent from frozen records is
`not_reported`, never estimated. Pipeline rows use the registered zero-LLM accounting;
external rows retain their recorded model/cost provenance. No timing benchmark is run.

## Stop conditions

This is a one-pass reanalysis. Data-schema or population mismatches are preserved in
the output status fields. They do not authorize changing the registered definitions,
rerunning methods, or modifying frozen assets.
