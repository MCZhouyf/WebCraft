## Stage 0: scope, delivered separately

Identify the actual records, run manifests and executing code for (a) the
author's 600 EXT-v2 episodes and (b) the 11,220 main-matrix episodes. A shared
instance-name prefix is not evidence of a shared knowledge-delivery path.
Record counts/coverage, source hashes and line references. If the requested
dataset cannot be identified or its coverage contradicts the stated totals,
report that discrepancy and stop rather than substituting an adjacent run.

Trace the complete knowledge path from initial evidence acquisition through
adapter/wrapper, per-action context construction and any persistent planner
state. Classify each dataset as inside, outside or unresolved for the specific
defect: required initial injected knowledge is supplied once and omitted from
subsequent stateless action requests after observation replacement. Also check
equivalent once-only paths, not just CDSKnowledgeAdapter by class name.

For retrieval systems, distinguish: (i) LLM action-request context retention,
(ii) persistent evidence/compiled-operator/belief state in deterministic
planners, and (iii) bounded recent observations. If no LLM action requests
exist, say so and audit the evidence object's lifetime instead of asserting
that every passage appears in a nonexistent prompt. Bound any conclusion to
the verified record set and code path.

Use only saved prompts/observations, existing records and source reads. Do not
import or instantiate simulator or gateway clients. Avoid excerpts containing
endpoints or credentials. No key or endpoint belongs in reports or commits.

If EXT-v2 is inside the scope, deliver stage 0 and STOP for author instructions.
If scope or counts remain unresolved, likewise report and stop. Even if both
sets are outside, deliver stage 0 separately before any stage-1/2/3 calculation.
