# A10 BIA sanity check

Registration date: 2026-10-16. This is a deterministic analysis of frozen A8
CDS episode exports, A8 action logs, and A8/A9 derived tables. It makes no
model call, runs no environment episode, does not change a frozen method or
prompt, and treats `/root/autodl-tmp/webcraft` as read-only. It does not alter
any previously reported metric.

## Inputs and coverage

The input is the completed 416-episode A8 CDS matrix and its existing
`episode_metrics.csv`, `stale_action_audit.csv`, saved episode records, and
the already registered A8 first-run query-follow-up summary. Coverage must be
exactly Direct LLM x `{K, K+S, empty}` and ReAct x `{K, K+S, S, empty, K+N}`;
each cell contains the same 52 frozen CDS instances. Missing or extra episode
records are a hard error.

All paired interval estimates first average episode values within the existing
`family_id`, then draw 10,000 independent-family percentile bootstrap samples
with NumPy seed `20261017`. A result is described as greater only if its 95%
interval lower endpoint is strictly above zero.

## 1. Comparator sanity table

For every method-condition boundary-question item, retain the frozen gold
validity label and evaluate the following deterministic comparators:

1. `always_invalid`: every candidate is invalid.
2. `newest_timestamp`: candidate(s) at the maximum frozen timestamp are valid;
   all others are invalid.
3. `context_present_valid`: a candidate is valid when its normalized mechanism
   fact occurs in the frozen initial visible material or an already saved
   public-search result; otherwise invalid.

For every condition and comparator report gold valid and invalid counts;
valid and invalid recall; unweighted accuracy; and balanced accuracy. The
corresponding agent rows use answered items for recall/accuracy and retain an
explicit uncertain count and rate over all items. The report will assess
whether a comparator balanced accuracy of 0.5 is forced by the CDS candidate
construction using these component counts; no premise is inferred from the
result.

## 2. Agent response distributions

For Direct and ReAct in every completed condition, report all boundary items
as `valid`, `invalid`, or `uncertain`, with counts/proportions, plus valid and
invalid recall. A response distribution is descriptively labelled degenerate
only when one of those three labels occupies at least 95% of all items. This
label is not a performance metric.

## 3. Discriminative-probe strata

Use the frozen A8 per-episode `discriminative_probe` field without rescoring
the action trace. For each Direct/ReAct method-condition cell and each stratum
(`probe=1`, `probe=0`), calculate answered-item BIA. For a method's available
conditions, compare `probe=1 - probe=0` on matched instance IDs when both
episode values are defined; report each condition and the pooled condition
rows. The pooled point estimate and interval use the family bootstrap above.

## 4. Query-follow-up tables

Re-export the A8 first-run five-method counts with their original four fixed
classes: `denied_then_target_valid`, `denied_then_stale`, `not_denied`, and
`no_related_followup`. Separately calculate the same classes for A8 CDS K+S
using the A8 registered query classifier and saved action logs, with a
per-method denominator equal to the number of discriminative query contacts.
No new classifier or semantic-action rule is introduced.

## Outputs

Write all output under `reports/main/post_review/a10_bia_sanity/`: comparator
cells, agent response distributions, probe-stratum values and paired tests,
first-run and CDS K+S query tables, and `REPORT.md`. Results are reported
regardless of direction. The report states explicitly whether the observed
0.5 comparator BIA is a construction consequence or identifies a concrete
calculation/data cause.
