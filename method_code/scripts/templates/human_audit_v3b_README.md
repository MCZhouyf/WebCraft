# v3b / CDS v3 复核说明

这是为既有人工复核补充的冲突对证据，不是新智能体输入，也不是重新评分。
不调用 LLM、不运行新回合、不改动原 v3 表、CDS 原表、WebCraft 或 audit_key。

## 哪些行需要复核

- `audit_sheet_v3b.csv`：只含原 v3 标有“证据未决，待裁决”的 37 行。原 v3 的判断和备注在 `prev_*_v3`；本轮三个标注列留空，不能把格式占位的“无”当作已确认无接触。
- `audit_sheet_cds_v3.csv`：原有 30 行全部补齐冲突对。可用的既有人工值直接保留，原值另存 `prev_*_cds_v2`。只需复核未决行；历史“查询+执行”保留在 prev 列，新 contact_type 留空，请按本轮允许值确认格式，不自动替你裁决。
- 不再填写已废弃的 `terminal_depends_on_stale`；新表不导出该列。

## 允许填写的值

`contact_type` 只能填 **无 / 查询 / 执行 / 无法确定**。查询与执行都有时填“执行”，在 notes 注明两者均有。
证据不足时填“无法确定”，不要用“无”占位。

`propagation` 仅在 contact_type 为“查询”或“执行”时填写 **是 / 否 / 无法确定**；
contact_type 为“无”或“无法确定”时必须留空。notes 请写明具体步号与依据，或缺少何种证据。
prev 列只是既有人工意见，不是评分器标签，不要求按它作答。

## 怎样读新增证据

四个冲突对字段按 `[1]`、`[2]` 等编号相互对应。一个任务中的所有冻结冲突均保留，不依据本回合最终表现筛选。
`stale` 指不适用于当前世界的说法，不保证其年代更早；旧世界中较新的说法也可能不适用。

原始主矩阵冲突库保存的是结构化断言，字段明确标为“冻结断言原文（JSON）”，不假装是 Wiki 逐字引文。
来源是冻结版本机制记录或其中的配方资源 ID；对于不存在的机制，明确写为否定/缺失，不虚构另一条配方。
CDS 另外保留冻结注入材料的字面句子、来源与时间戳。

`stale_predicted_output` 列出输入槽、数量、产物及对比反馈。每个输入槽消耗 1 个物品；槽内多个 ID 是备选，
不是全部一起消耗。3×3 摆放中的 null 是空位。掉落目录原本只声明可能物品集合；
确定性后端的数量与工具要求另行明确来源，不把可能集合误当数量。

`discriminating_action` 是机制级静态对比，不是声称该回合已经执行了这一步。合成/冶炼对比须有足量输入和燃料，
挖掘须满足工具前提；若某输入在一侧版本不存在，字段明确提醒不能在两侧控制齐输入，并给出名称查询对比（如存在）。
`mine` 的 block/node_type 是资源种类示意，真正接口执行须用观测到的 node_id；这里不执行接口。
目录原料范围或配方对象发生变化，并不代表旧摆法在新世界必然失效；默认探针同反馈时会明确提示。
“无可区分动作”仅在给定机制的完整有限摆法域查表得到同一产物/数量时输出，并列出检查范围与示例；
不据此推断其它机制或整个任务不可区分。

## 检索证据的限制（重要）

A12 已披露：片段进入模型上下文的依据是对既有记录的**重建**，而非逐步保存的完整模型提示。
本次沿用原表片段，不把“重建的返回/上下文片段”升级为“已经直接核验每次请求收到的证据”。
判断以**冲突对与执行时的世界反馈为主，检索片段为辅**；不能仅因某句出现在片段块里就推定智能体依赖它。
CDS 首次观测中的完整注入事实可以用于定位冻结材料，但不证明该事实在后续每次请求中仍被保留。

`search_ownership` 按原表完整片段块拼接后逐字相等列出共享范围；同 task、同 condition 的方法单列，
跨任务/条件的相同块也完整列出。无检索说明的相等也计为相同块，并不表示实际检索了同一批文档。
重复块不得作为另一回合独立保留知识的证据。CSV 既有拆列原样保留，按 part 后数字顺序拼接，不按表头物理位置。
原表表面单元格的“41 个不同块、11 个共享块”中有 10 个共享组是重复的拆列提示文字；
实际拼接后是 65 个不同片段块、7 个共享组。不要把相同的“见 search_part…”当成片段内容相同。
新增长字段若超过 30,000 UTF-16 单元，也按对应 `*_part1`、`*_part2` 等列无损拆分；没有静默截断。
